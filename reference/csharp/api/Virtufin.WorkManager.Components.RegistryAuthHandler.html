HTTP message handler that injects HTTP Basic credentials into outbound requests to the configured Gitea package registry. Used by the WorkManager's IHttpClientFactory-managed CodeFetcher client so it can download worker code-source artefacts -- both .nupkg (NuGet, .NET workers) and .whl (PyPI, PythonWheelEngine's wheel-bundle workers) -- from a private Gitea registry (e.g. https://gitea.haenerconsulting.com/api/packages/virtufin/nuget/package/... or .../api/packages/virtufin/pypi/files/...) without requiring public-read access on the registry. Despite the historical name, it is registry/ecosystem-agnostic -- it matches purely on request host, not on package type.

Remarks

Credentials are read from environment variables at handler construction:

  • VIRTUFIN_REGISTRY_USER — typically buildbot.
  • VIRTUFIN_REGISTRY_TOKEN — a Gitea personal access token. Needs read:repository scope, not just read:package/write:package -- the latter is sufficient to list/manage packages but not to download raw package files from a private-repo project (confirmed live: a token with only read:package/write:package gets a 404, not a 401, fetching a .whl file this way -- Gitea masks the permission failure as "not found" rather than "forbidden").

The handler only injects the Authorization header for requests whose URL host matches one of the configured RegistryHosts (case-insensitive exact match). Requests to other hosts are passed through unchanged, so non-Gitea code-source URLs do not leak credentials. The default list is nuget.haenerconsulting.com (a legacy DNS alias) and gitea.haenerconsulting.com (the canonical Gitea host) -- both resolve to the same backend.

This is intentionally scoped: a future move to a different registry (e.g. nuget.org, GitHub Packages) only needs a handler variant or a richer routing config — the public IHttpClientFactory consumer in WorkManager.FetchFromUrlAsync is unchanged.
